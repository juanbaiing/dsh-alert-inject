# dsh-alert-inject

> **在模型正式回答之前，先把"你可能已经忘了／看漏了"的东西重新摆到它眼前。**
>
> 一个 DeepSeek Harness（DSH）插件。**零第三方依赖、零常驻服务、不调 LLM。**

> 📖 **想先了解它为什么存在、解决了什么问题？** → [读这篇](ARTICLE.md)
> （那篇是"为什么你会想要它"；本文件是"怎么让它跑起来"——**两者目标不同**）

**⚠️ 它只在你【给它参照物】时才真正有用。** 装完不配任何东西，它只会安静地说"无异常"。
→ 想 5 分钟看到效果，直接跳到 [三、五分钟看到效果](#三五分钟看到效果最省事的验证路径)。

## 一、环境要求（务必先看）

### 必需

| 项 | 要求 | 说明 |
|---|---|---|
| **运行环境** | **DeepSeek Harness（DSH）** | ⚠️ **不是通用插件**：它注册工具用的是 `@deepseek-ai/dsh-tools`，读的是 DSH 的会话日志格式（`~/.dsh/sessions/*/session.jsonl.zstd`）。**Claude Code / Cursor / 通用 LLM 直接用不了。** |
| **Node** | ≥ 18（用到了 `node:zlib` 的 zstd） | 实测于 Node 24 |
| **第三方依赖** | **无** | `package.json` 的 `dependencies` 为空 |

### 可选（不装也能跑，只是部分功能关闭）

| 项 | 用在哪 | 不装会怎样 |
|---|---|---|
| **Ollama + `bge-m3`**（约 **1.1 GB**） | 语义检索、知晓感（FOK）、新颖性 | 这三项静默关闭，**其余全部照常** |

**依赖它的三项之外的，全是纯程序**（判据扫描、重复检测、引用检查、锚点、语境分块、知识层图遍历、知识抽取）。

### 性能实测（供你预估）

| 操作 | 实测 |
|---|---|
| 一次 `alert_check`（零配置） | **约 0.6~0.9 秒** |
| 一次 `alert_check`（含 embedding） | **再 +0.1~1.2 秒**（取决于文本长度） |
| **首次建索引** | ⚠️ **120 条约 15 秒；全量（约 1100 条）约 8 分钟**（约 450ms/条，Ollama 串行） |
| 索引之后每次检索 | 约 0.1 秒（纯 CPU 余弦比对只要 3.4ms） |

**⚠️ 首次建索引是唯一的"重活"** —— 见第四节。

## 二、它是什么

**三类声音：**

| 声音 | 例子 |
|---|---|
| **「你本来在干什么」** | 目标、子目标、以及"这个目标被动过" |
| **「这个之前好像发生过」** | 与当前内容语义相近的较早位置（**只给位置，不给原文**） |
| **「这不对吧」** | 引用了不存在的文件／正在自我重复／当前语境内有可疑痕迹 |

**它不是什么**（这三条同样重要）：

- **不是记忆数据库** —— 那是 OpenViking／Mem0 那一类的定位（存得下、取得到）。**它的定位是"没人问的时候也要响"。**
- **不是拦截器** —— 它只提醒，不阻断。
- **不做语义判断** —— "这两句是否矛盾"这类判断，本项目**两次实测失败**（NLI 三版全败；向量比对方向差 −2.8pp 且方向相反）。**别让它做它做不到的事。**

### 与既有方案的差别（作者实测过 OpenViking 后总结）

| | 记忆库（OpenViking 等） | 本插件 |
|---|---|---|
| 形态 | 工具／数据库（实测 **15 个 MCP 工具占约 1.7k token 常驻**） | **2 个工具**，静态指令落缓存前缀 |
| 触发 | **模型主动调**（"加载按需来"） | **回答前自动被提醒去调** |
| 缓存 | 自动召回**会打断前缀缓存** | **不打断**（静态文本） |
| 目标 | **存得下、取得到** | **没人问的时候也要响** |

## 三、五分钟看到效果（最省事的验证路径）

**装完不配任何东西 ⇒ 它只会安静地说"无异常"。** 因为**它需要参照物**。最短路径：

### ① 装

```bash
# 在 DSH profile 的 node_modules 下放好本包，然后在 profile 的 cordis.patch.yml 里加：
- insert:
    - id: dsh-alert-inject
      name: dsh-alert-inject
```

**⚠️ 必须重启 DSH**（若 `dsh-super-injector` 被禁用，则没有热注入通道）。

### ② 让它在你的项目里"有得可比"

它按约定在这些**相对路径**下找参照物（第一个命中的生效）：

| 参照物 | 候选路径 | 缺了会怎样 |
|---|---|---|
| **判据表** | `※世界模拟/回想/.警报判据.json`、`回想/.警报判据.json`、`.dsh-alert/judges.json`、`alert-judges.json` | 「这不对吧」的判据扫描关闭 |
| **术语表** | 同上目录下的 `_术语表.md` | 判据的"与门"失效（会变宽松） |
| **知识图** | 同上目录下的 `_graph.json` | 「相关的档」召回关闭 |

**⇒ 最小可行配置：** 只要放一个 `alert-judges.json` 到项目根，形状如下：

```json
{
  "meta": ["（自指防护词，命中则不报，防止讨论机制本身时刷屏）"],
  "judges": [
    { "id": "我常犯的错", "sources": ["正文"],
      "signals": ["应该已经", "都改好了", "肯定能跑"],
      "anomalies": [], "requireTermHit": false, "enabled": true }
  ]
}
```

**⇒ 然后让模型在其间写一句含"应该已经"的话，再调 `alert_check` —— 它会报出来。**

### ③ 确认它到底有没有在工作（**用诊断，别靠猜**）

```js
import { diagnose, renderDiagnose } from './lib/config.js'
console.log(renderDiagnose(diagnose({ cwd: '你的工作区路径' })))
```

它会**逐条**告诉你：哪个路径没找到、哪个工作区不匹配、**缺哪一项会关掉哪个功能**。

> **为什么强调这个**：作者装过的记忆库"感觉不好、没能实现"，最常见的原因就是
> **"不知道它到底在不在工作"**。所以本插件必须能自报状态。

### ④ 想用语义检索（可选）：建一次索引

```bash
node lib/librarian.js <会话文件>            # 建索引（约 15 秒 / 120 条）
node lib/librarian.js <会话文件> "查询文本"   # 直接查
```

**⚠️ 索引有上限（`LIBRARIAN_MAX`，默认 120 条）**，覆盖不足时会**主动告警**，
例如：`（⚠️ 本次检索只覆盖了会话的 22%——更早的内容未参与检索）`。
—— 宁可暴露局限，不给虚假的完整感。

## 四、怎么用（两种）

### ① 作为工具（推荐）

模型在正式回答前**主动调用一次** `alert_check`，拿到一份简短报告再回答。
另有一个 `knowledge_extract`，用来**从文档里抽知识**（见第五节）。

**为什么是"工具 + 静态指令"而不是"自动注入"**（三代试错换来的）：

| 版本 | 做法 | 结果 |
|---|---|---|
| v1 | 注入 system prompt，每轮跑 | **打断前缀缓存** + 读 reasoning 通道 ⇒ 招来瘟疫 |
| v2 | 插一条消息 | 插在数组最前 ⇒ **前缀缓存全废** |
| **v3** | **工具 + 静态前置指令** | ✅ 静态文本落缓存前缀，不打断 |

### ② 作为库

```js
import { buildReport } from './lib/report.js'
const r = await buildReport(cwd)      // { sections, text, meta }
console.log(r.text)
```

| 模块 | 做什么 |
|---|---|
| `index.js` | 判据扫描（`alertText`）／指针回取（`peek`）／工具注册 |
| `report.js` | **总装**：把各检测器汇总成一份报告（按预算裁剪） |
| `anchor.js` | 锚点：目标／子目标／约束（**含"目标被动过"提醒**） |
| `blocks.js` | 语境分块（按用户每次发言切）—— **降误报的关键** |
| `knowledge.js` | 知识层：遍历设定图（cooccur 优先，向两侧递减） |
| `librarian.js` | 会话内语义检索（bge-m3） |
| `repetition.js` | 重复检测（纯统计，**误报实测 0%**） |
| `reference-check.js` | 引用存在性（查文件系统） |
| `fok.js` / `novelty.js` | 知晓感／新颖性（复用检索结果，不另建索引） |
| `learning.js` | 学习循环（发现→求证→入待审） |
| `extract.js` | 知识抽取（**提示词 + 防幻觉校验**） |
| `samples.js` | 样本层（**"能长起来"的前提**） |
| `config.js` | 配置 + 诊断 |

## 五、从文档里长知识（`knowledge_extract`）

**插件不调 LLM**（它没有那个能力），所以分工是：

```
① knowledge_extract(mode="prompt", doc=路径)
     → 返回【抽取提示词 + 原文】
② 模型自己按提示词产出 JSON
③ knowledge_extract(mode="verify", json=..., source=原文)
     → 程序【逐字核对】每条的证据（evidence/quote 必须真的出现在原文里）
       · 对不上 ⇒ 判定为编造，丢弃并留痕
       · 对得上 ⇒ 转入【待审记】（**不直接入图**）
```

**⇒ 关键在③：模型可以编，但编的会被子串比对拦下来。** 实测混入一条违规的 `gate` 边，
被正确拒绝并给出理由（`gate` 是"读者的门"，按规矩只能手写）。

**实测一次**：候选 5 条 → 原文可核 4 条 → 入待审 6 条（含此前累积）。

## 六、它报出来的东西长什么样

**核心尺度：像一个声音，不像一份报告。** 实测演进（这条曲线本身是设计的一部分）：

| 版本 | 长度 | 读者感受 |
|---|---|---|
| 初版 | **608 字，76% 是列表** | 像仪表盘 |
| 中间版 | 207 字，但无所指 | **礼貌的空话**（"我查了没找到"） |
| **现在** | **60 字左右** | 像提醒 |

```
🧩 已换过 59 段话题 —— 主线目标值得回头确认一次（当前在谈：…）
```

**两条硬规矩：**

1. **没值得说的就不出声**（借 `dsh-plugin-save-token` 的 **never-worse 门控**：
   不值得占位的东西不发出去）。**"我查了，没找到"不构成信息。**
2. **一旦出声，必须有所指**：要么**指向具体位置**（`pos=…`），要么**指出某个模式**（"已换过 N 段话题"）。

## 七、⚠️ 五条设计红线（改代码前必读）

### ① 输出**绝不回显触发词**
报一次 = 把命中词写进上下文 = 下一轮又被匹配 = **自我喂食**（`REPORT.md` §二·v4 的病因）。
**改任何对外文本后，必须跑：**
```bash
node leak-check.mjs <projectRoot>
```
> 这个检查已累计抓出 **5 次**真实泄漏（**包括写检查工具的人自己踩的**）。
> 实测教训：**用正则从源码里"猜"文本是不可靠的** —— 它会漏（曾漏掉一个多行拼接的前置指令）。
> ⇒ 现在的做法是**直接 mock ctx 调用 `apply()`，抓真实文本**（单一真相源）。

### ② 只给**指针**，不给内容
要原文，用 `peek(pos)` 按指针取。**这是 déjà vu 的 `decoupled familiarity`**：
只发"这事发生过"的信号，不把内容一起送上来。

### ③ 不注入到会被回传的通道
`reasoning` 是**强制回传**通道（且只在带工具调用的轮次回传）。
**往里写东西 = 下一轮必然被自己看见。**（读取无害；**注入**才是病因。）

### ④ 有界容器超限时【归档】，绝不【静默丢弃】
> **一切结果留痕** —— 不留痕的结果等于没发生。
`samples.js` 是轮转（对）；`learning.js` 曾错误地 `slice(-500)` 静默截断（**已修为归档**）。
**参考实现在 `learning.js` 的 `archiveOverflow()`：归档失败 ⇒ 不裁剪**（宁可文件变大，也不丢数据）。

### ⑤ 工具返回值必须是**无损 JSON**（挂载后才发现的那类）
> 实测坑（**挂载后首次调用才发现**）：返回 `{ note: undefined }` ⇒ DSH 拒收整个返回值
> （`value is not lossless JSON`）。**离线调用测不出来**（本地不经 DSH 序列化）。
> ⇒ 现已统一过 `toLosslessJson()` 闸门，并有专门断言。

## 八、可调参数（都有合理默认，不改也能跑）

```bash
DSH_ALERT_MAX_LINES=8      # 判据段最多几行
DSH_ALERT_SCAN=0           # 0=全量扫痕迹
ALERT_BUDGET=2400          # 报告总字数预算
ALERT_NO_RETRIEVAL=1       # 关掉需要 embedding 的部分
ALERT_LEARNING=1           # 打开学习循环（**有副作用**：写样本+入待审）
KNOW_GATE_W=0.3            # 图遍历里 gate 边的权重折扣
KNOW_LAYER_DECAY=1.0,0.6,0.35,0.2,0.15   # 按 rank 距离的层衰减
LIBRARIAN_MAX=120          # 索引上限（⚠️ 越高越贵：embed 约 450ms/条）
LIBRARIAN_MIN_DIST=3       # 近处排除半径
SAMPLES_MAX_MB=64          # 样本文件轮转阈值
```

**配置文件**（可选）：`~/.dsh/alert-inject.json`

```json
{ "workspaces": [], "projectRoot": "D:\\你的项目", "dataDir": "C:\\Users\\你\\.dsh" }
```
> `workspaces` 为**空数组** = 对所有工作区生效（这是发布后的正确默认）。
